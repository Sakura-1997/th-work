# 考试平台系统业务全景说明（第一版）

> 本文根据当前仓库中的四个前端、`spt` 后端、数据库脚本和业务文档整理。后端代码和数据库字段是主要依据；如果前端文案与后端不一致，以后端为准。

## 1. 系统边界

项目包含四个业务端和一套后端服务：

| 系统 | 面向对象 | 主要事情 |
|---|---|---|
| `赣服通app` | 考生/个人用户 | 办事指南、培训报名、考试报名、缴费、准考证、成绩、证书、评价、纠错 |
| `培训机构` | 培训机构工作人员 | 培训项目、培训计划、班级、课程、学员、教师、考试报审、档案和报表 |
| `监管机构v3.0` | 省级/市级/区县监管人员、考试机构管理人员 | 机构管理、项目和课程配置、考试资格审批、考试实施、收费规则、统计、档案监管 |
| `实操考试app` | 实操考试工作人员/考评员 | 实操考试计划、考生、设备、题目、评分和成绩提交 |
| `spt` | 所有前端的服务端 | 登录权限、培训、考试、审批流、支付、证书、电子签名、国家平台同步、消息和统计 |

## 2. 一句话业务主线

```text
监管配置机构和项目
  → 培训机构创建培训计划和班级
  → 考生报名并提交材料
  → 培训机构审核、培训和记录学时
  → 培训机构提交理论/实操考试报审
  → 市级或省级监管审批
  → 考生缴费、领取准考证并参加考试
  → 录入/公布理论和实操成绩
  → 审核发证并同步国家平台
  → 复训、换证、继续教育、档案和统计
```

## 3. 角色和职责

### 3.1 考生

- 在赣服通端查看办事指南和可报名项目。
- 填写个人信息、工作信息和申请材料，完成电子签名。
- 选择或参加培训，查看培训进度和学时。
- 查看考试申请、缴费、准考证、成绩和证书。
- 对培训机构或监管服务进行评价，必要时提交证书信息纠错。

### 3.2 培训机构

- 维护机构信息、备案机关、教师和培训资质。
- 选择培训项目，创建初训/复训培训计划。
- 创建班级，安排课程、教师、教室和考勤。
- 导入或录入学员，完成班级内审。
- 对完成培训的学员发起考试报审。
- 查看考试、培训档案和报表。

### 3.3 考试中心/考试点

- 维护考试工作人员、考场、考试点和考试设备。
- 组织理论考试和实操考试。
- 处理考试报名实例、签到、成绩和结果公布。
- 实操考试端负责实操过程和考评结果。

### 3.4 市级、省级监管部门

- 审核培训计划、考试资格和考试计划。
- 按业务层级查看本级数据。
- 配置项目级别、课程、考试收费规则和办事指南。
- 管理培训机构、考试机构、考试点、教师和考评员。
- 查看学员档案、考试档案、证书和统计数据。

### 3.5 发证机关/国家平台

- 对符合条件的考试结果进行发证处理。
- 处理特种作业证书初领、复训、复审、换证。
- 与国家安全生产知识技能考核信息系统进行数据互通。

## 4. 核心业务对象

| 对象 | 代码/表 | 大白话解释 |
|---|---|---|
| 人员类型 | `tr_qualification` 的路径首段 | 特种作业人员、主要负责人、安全生产管理人员等 |
| 作业类别 | `tr_qualification` 的路径第二段 | 电工作业、焊接与热切割作业等 |
| 操作项目 | `tr_qualification` 的末级项目 | 低压电工作业、高压电工作业等具体项目 |
| 资格类别 | `tr_qualification.category` | I类、II类、其他类 |
| 培训项目 | `tr_project` | 某个资格项目的初训/复训配置 |
| 培训计划 | `tr_training_plan` | 培训机构准备开设的一期培训计划 |
| 班级 | `tr_class` | 培训计划实际落地的班级 |
| 班级学员 | `tr_class_trainee` | 学员和班级的关系，区分意向入班、正式入班和内审状态 |
| 培训报名 | `tr_trainee_signup` | 学员报名某个培训项目的记录 |
| 考试报审 | `exm_exam_apply_trainee` | 培训机构提交给监管审批的考试资格申请 |
| 考试计划 | `exm_exam` | 某场理论或实操考试的计划 |
| 考试报名 | `exm_exam_signup` | 学员报名某场考试的汇总记录 |
| 考试实例 | `exm_exam_signup_instance` | 学员在某一轮、某一场考试中的实际记录 |
| 证书 | `tr_certificate`、`tr_national_certificate` | 考试合格后的本地证书和国家平台同步记录 |

| 审批机关 | 考试报审 `current_approval_org` | 当前这条考试申请由哪个监管机构处理 |

## 5. 培训业务流程

### 5.1 项目和计划

1. 监管端维护资格项目、项目级别、初训/复训可用状态、学时和课程。
2. 培训机构选择自己有权限开展的资格项目。
3. 培训机构创建培训计划，填写培训类型、时间、地点、人数和备案机关。
4. 后端按资格项目和培训类型计算理论/实操应修学时。
   - 初训：取初训理论学时 + 初训实操学时；
   - 复训：取复训理论学时，实操学时为0。
5. 计划可以自动报备，也可以保存后再报备。

### 5.2 备案机关

后端当前规则是“按培训机构配置的候选项选择”：

- 候选项来自当前机构的 `examRecordId` 和 `examRecord` 配置；
- 只有一个候选项时自动使用；
- 有多个候选项时必须选择；
- 选择的机关ID必须属于当前机构配置；
- 代码没有根据I类/II类自动选择省厅或市厅的逻辑。

实现位置：`spt-train-biz/.../TrainingPlanServiceImpl.java` 的 `fillFilingAuthority`。

### 5.3 班级和学员

- 班级状态：培训报名 → 待培训 → 培训中 → 获取学时 → 待归档 → 已归档。
- 班级学员状态：意向班级 → 正式入班。
- 学员内审状态：未审批、通过、不通过。
- 培训机构可以录入、批量导入、调整班级学员，并维护课程、教师、教室和考勤。

## 6. 考试报审和审批流

后端在提交考试报审时，会从学员报名关联的班级、培训项目和资格项目读取：

- `tq.category`：I类/II类/其他类；
- `tp.type`：初训/复训。

### 6.1 后端实际流程规则

| 资格类别 | 培训类型 | 流程编码 | 实际含义 |
|---|---|---|---|
| I类 | 初训 | `FLOW_PROVINCE` | 直接由省级审批 |
| I类 | 复训 | `FLOW_CITY_PROVINCE` | 先市级，再省级 |
| II类 | 初训 | `FLOW_CITY_PROVINCE` | 先市级，再省级 |
| II类 | 复训 | `FLOW_CITY_PROVINCE` | 先市级，再省级 |
| 其他类 | 省级考试中心 | `FLOW_PROVINCE` | 省级审批 |
| 其他类 | 非省级考试中心 | `FLOW_CITY` | 市级审批 |

实现位置：`spe-exam-biz/.../ExamApplyTraineeServiceImpl.java` 的 `determineFlowCode`。

### 6.2 I类复训特殊限制

I类复训不能选择省级考试中心，也不能不选考试中心，必须选择地市考试中心。提交后初始状态为“待市局审批”，市局通过后才进入省厅审批。

### 6.3 审批状态

- `0`：待报审；
- `1`：待市局审批；
- `2`：待省厅审批；
- `3`：审批通过；
- `4`：市局审批不通过；
- `5`：省厅审批不通过。

## 7. 理论考试和实操考试

### 7.1 理论考试

- 监管/考试机构配置考试计划、考试时间、考场、考试方式和工作人员；
- 审批通过后生成或开放考试报名；
- 学员按报名状态缴费、领取准考证、参加考试；
- 结果进入考试报名和考试实例记录。

### 7.2 实操考试

- 特种作业初训通常需要理论和实操两部分；
- 后端发证判断使用考试报名行的 `project_type`；
- 特种作业初训理论和实操都合格后才满足发证条件；
- 实操考试端负责设备、题目、考评和成绩提交。

### 7.3 考试报名状态

- `0`：待报名；
- `1`：待缴费；
- `2`：待出结果；
- `3`：合格；
- `4`：不合格。

## 8. 缴费

缴费规则由监管端维护，后端按资格类别、考试机构、理论/实操考试类型和收费配置计算。

当前代码中：

- 特种作业考试需要缴费；
- 主要负责人和安全生产管理人员通常不收考试费；
- 一类规则要求使用全局范围；
- 二类规则要求绑定具体考试机构。

具体收费金额以收费规则配置和订单实际记录为准。

## 9. 发证、复训和换证

1. 考试成绩公布后，系统筛选发证候选人。
2. 发证判断读取考试实例中最新一条已公布且合格的成绩。
3. 特种作业初训要求理论、实操均合格；复训走旧证关联和换证窗口校验。
4. 复训证书要求在原证有效期结束前60天起申请。
5. 证书生成后可同步国家平台；同步失败会保留本地状态并支持后续处理。
6. 证书有效期内可办理复审，满足年限条件时可延长复审时间或换证。

## 10. 权限和数据范围

监管机构业务层级代码为：

- `1`：国家级；
- `2`：省级；
- `3`：市级；
- `4`：区/县级。

证书查询的后端数据范围目前体现为：

- 省级范围包含“特种作业I类初训”和非特种省级发证数据；
- 地市范围包含本市考试中心对应的其余特种作业数据和本市发证机关对应的非特种数据。

## 12. 当前已发现的业务风险和待确认项

1. **备案机关没有按I类/II类自动绑定。** 当前只是培训机构候选项选择，若要实现“I类省厅、II类市厅”，需要新增后端规则。
2. **备案机关和审批机关容易混淆。** 培训计划的 `filingAuthority` 与考试申请的 `currentApprovalOrg` 不是同一个字段、也不是同一个业务动作。
3. **前端存在类别和初训/复训混用风险。** 后端使用 `category` 判断I/II类、使用 `projectType` 判断初训/复训；部分前端代码的变量命名和比较逻辑不够清楚。
4. **II类考试中心的限制需要产品确认。** 后端将II类统一路由到“市级→省级”，但在考试报审服务中没有像“I类复训”那样单独拒绝省级考试中心。
5. **部分旧接口和新接口并存。** `spe-exam-biz` 与 `spt-train-biz` 都有考试、报名、课程等控制器，后续需要按实际网关路由确认哪个是当前生产入口。
6. **免培、省外报考、证书纠错和继续教育是独立分支。** 它们不能完全套用普通培训班流程，需要单独画流程图和补充字段说明。
7. **机构状态的代码命名和中文含义相反。** `InstitutionStatusEnum` 中 `NORMAL("1")` 的中文是“停用”，`DISABLE("0")` 的中文是“正常”。业务判断不能只看英文常量名，需要确认数据库中 `0/1` 的真实含义后统一修正。

## 13. 建议的后续梳理顺序

1. 角色和主流程已经过业务确认，结论为符合；
2. 本轮不继续展开“页面 → 接口 → Service → Mapper → 数据表”对照；
3. 状态值和专题分支见下文；
4. 需要业务确认的规则另见 `docs/业务规则确认表.md`。

## 14. 状态流转总表

同一个人会同时存在多组状态。例如“培训报名审核通过”不等于“考试资格审批通过”，因此页面展示时不能把不同状态混成一个。

本章只整理会随着办理过程变化、并且会影响下一步操作的业务状态。性别、学历、考试类型、资格类别等固定分类不算状态。

### 14.1 培训报名审核状态

| 状态值 | 含义 | 常见去向 |
|---|---|---|
| `3` | 草稿 | 补齐后提交，进入待审核 |
| `0` | 待审核 | 审核通过或审核不通过 |
| `1` | 审核通过 | 可继续入班、培训、签申请表和报考 |
| `2` | 审核不通过 | 修改资料后重新提交 |

### 14.2 报到和记录状态

| 字段 | 状态值 | 含义 |
|---|---|---|
| `checkInStatus` | `0` | 未报到 |
| `checkInStatus` | `1` | 已报到 |
| `recordStatus` | `0` | 正常报名记录 |
| `recordStatus` | `1` | 已从业务中剔除 |
| `trainingQualifyStatus` | `0` | 培训不合格 |
| `trainingQualifyStatus` | `1` | 培训合格 |

### 14.3 班级状态

```text
培训报名(0)
  → 待培训(1)
  → 培训中(2)
  → 获取学时(3)
  → 待归档(4)
  → 已归档(5)
```

班级处于“培训报名”和“待培训”时可以正常加入；培训已经开始时，仅开始当天仍可按后端规则加入。

### 14.4 申请表签署状态

```text
未发起(NOT_STARTED)
  → 准备中(PREPARING)
  → 待签字(PROCESSING)
  → 已签字(DONE)
```

异常或人工处理分支：

- `FAILED`：签署失败，可以重新发起；
- `CANCELED`：已撤销，可以修改资料后重新发起。

### 14.5 考试资格审批状态

省级流程：

```text
待报审(0) → 待省厅审批(2) → 审批通过(3)
                         └→ 省厅审批不通过(5)
```

市级流程：

```text
待报审(0) → 待市局审批(1) → 审批通过(3)
                         └→ 市局审批不通过(4)
```

市级、省级两级流程：

```text
待报审(0)
  → 待市局审批(1)
  → 待省厅审批(2)
  → 审批通过(3)
```

市局或省厅不通过后，可以修改并重新提交；已经处于审核中或审批通过时不能重复提交。

### 14.6 考试报名状态

```text
待报名(0) → 待缴费(1) → 待出结果(2) → 合格(3)
                                      └→ 不合格(4)
```

考试报名实例另有状态：有效、已取消、已过期。补考通常会形成新的考试实例，不能只看报名汇总行判断某次考试结果。

### 14.7 国家平台推送状态

| 状态值 | 含义 |
|---|---|
| `0` | 未推送 |
| `1` | 已推送 |
| `2` | 推送失败 |
| `3` | 状态未知 |
| `4` | 推送中 |

推送失败可以补推；已经成功的记录不应重复推送。部分定时任务会处理未推送、失败或人工标记为待补推的记录。

### 14.8 培训计划和班级报备状态

培训计划备案状态：

```text
待备案(0) → 已备案(1)
          ├→ 已作废(2)
          └→ 已删除(3)
```

“已作废”和“已删除”是结束状态，不等于退回待备案。培训计划是否已被班级使用另有独立状态：未关联 `0`、已关联 `1`。

班级报备状态只有两种：待报备 `0` → 已报备 `1`。它与班级处于“培训报名、培训中、已归档”等哪个阶段是两套不同状态。

### 14.9 教师和机构状态

教师报审流程：

```text
待报审(0) → 待审批(1) → 审批通过(2)
                       └→ 审批不通过(3)
```

教师是否可用另有启停状态：禁用 `0`、启用 `1`。

机构状态枚举当前存在明显的命名冲突：英文常量 `NORMAL` 对应代码 `1`、中文“停用”；英文常量 `DISABLE` 对应代码 `0`、中文“正常”。在业务方确认前，只能按接口实际返回的中文和值处理，不能按英文名猜测。

### 14.10 考试计划、审批和实施状态

考试相关有三套容易混淆的状态：

| 用途 | 状态值 | 含义 |
|---|---|---|
| 考试审批 | `0` | 待报审 |
| 考试审批 | `1` | 待审批 |
| 考试审批 | `2` | 审批不通过 |
| 考试审批 | `3` | 审批通过 |
| 考试展示/发布 | `0` | 待报审 |
| 考试展示/发布 | `1` | 待审批 |
| 考试展示/发布 | `2` | 审批不通过 |
| 考试展示/发布 | `3` | 已发布 |
| 考试展示/发布 | `4` | 已删除 |
| 考试实施 | `0` | 考试实施中 |
| 考试实施 | `1` | 考试完成 |

普通顺序是“待报审 → 待审批 → 审批通过/已发布”，审批不通过后修改再报。考试报备中的单个学员另有状态：待审批 `0`、审批通过 `1`、审批不通过 `2`。

成绩公布状态只有未发布 `0`、已发布 `1`。发证判断不仅看“合格”，还要求成绩已经公布。

### 14.11 缴费和订单状态

缴费至少有三层状态，不能混用：

| 层次 | 状态 |
|---|---|
| 页面显示 | 未支付 `UNPAID`、已支付 `PAID`、支付失败 `FAILED` |
| 内部订单 | 已创建 `4`、支付中 `0`、已支付 `1`、支付失败 `2`、已关闭 `3`、异常成功 `5` |
| 考试实例缴费事实 | 未缴费、已缴费 |

内部订单通常从“已创建/支付中”进入“已支付”，也可能进入“支付失败、已关闭、异常成功”。其中“异常成功”表示支付结果存在冲突，对外仍按失败态展示，需要人工核对，不能直接当成正常已支付。

支付对账批次状态为执行中 `RUNNING`、成功 `SUCCESS`、失败 `FAILED`；发现差异后，处置状态为待处理 `PENDING` → 处理中 `PROCESSING` → 已处理 `RESOLVED`，也可以标记为无需处理 `IGNORED`。

### 14.12 证书状态

证书也有三套独立状态：

| 用途 | 状态值 | 含义 |
|---|---|---|
| 证书申请 | `0` | 待申请 |
| 证书申请 | `1` | 已申请 |
| 证书申请 | `2` | 申请失败 |
| 证书推送 | `0` | 待推送 |
| 证书推送 | `1` | 已推送 |
| 证书推送 | `2` | 推送失败 |
| 证书自身状态 | `1` | 正常 |
| 证书自身状态 | `2` | 冻结 |
| 证书自身状态 | `3` | 注销 |
| 证书自身状态 | `4` | 撤销 |
| 证书自身状态 | `5` | 失效 |
| 证书自身状态 | `9` | 违规 |

证书是否过期又是一个单独判断：有效 `0`、过期 `1`。因此“已推送”不代表证书当前仍有效，“申请失败”也不等于已有证书失效。

### 14.13 评价、整改和服务处理状态

- 是否评价：未评价 `0` → 已评价 `1`；评价结果另分好 `1`、中 `2`、差 `3`。
- 差评处理：待处理 `0` → 待整改 `1` → 整改中 `2` → 已归档 `3`。
- 整改结果：待整改 `1` → 整改中 `2` → 整改完成 `3`。
- 一般服务事项：待处理 `0` → 已处理 `1`。

### 14.14 实操考试过程状态

实操考试会话主流程：

```text
待开始(INIT)
  → 进行中(IN_PROGRESS)
  → 待终审确认(WAIT_FINAL_CONFIRM)
  → 已终审确认(FINAL_CONFIRMED)
```

`RESET` 表示会话已重置，是异常处理分支，不是正常完成。

单个实操科目的主流程是待开始 `PENDING` → 进行中 `IN_PROGRESS` → 已完成 `COMPLETED`；签名缺失时进入待补签 `NEED_RESIGN`，完成锁定后为 `LOCKED`。实操分段状态为进行中 `IN_PROGRESS`、已完成 `COMPLETED`、已释放 `RELEASED`。

平板端考生状态比较简单：待考 `0` → 已完成 `1`。

### 14.15 作弊审核和上报状态

作弊记录审核状态：待审核 `PENDING_REVIEW` → 审核通过 `APPROVED` 或审核驳回 `REJECTED`。

审核通过后的国家平台上报状态单独记录：待上报 `PENDING` → 上报中 `PROCESSING` → 上报成功 `SUCCESS`；失败进入 `FAILED`，无法确定结果进入 `UNKNOWN`。这套状态不能和普通约考信息的国家平台推送状态混用。

### 14.16 其他支撑流程状态

| 业务 | 状态集合或流转 |
|---|---|
| 省外报考资料 | 草稿 `0` → 审核中 `1` → 审核通过 `2` / 审核不通过 `3` |
| 报名申请表更正 | 更正中 `OPEN` → 已完成 `COMPLETED` |
| 在线培训同步 | 待处理 `PENDING` → 处理中 `PROCESSING` → 成功 `SUCCESS` / 失败 `FAILED` / 已取消 `CANCELLED` |
| 考勤表格导入 | 待处理 `PENDING`、处理中 `PROCESSING`、已完成 `COMPLETED`、成功 `SUCCESS`、失败 `FAILED`、跳过 `SKIPPED`；代码没有把这些值写成唯一固定顺序 |
| 转班关系 | 生效中 `ACTIVE` → 撤销中 `REVERSING` → 已撤销 `REVERSED`；也可能进入后续流程终止 `JOURNEY_TERMINATED` |
| 学时证明业务版本 | 当前 `CURRENT` → 已被新版本替代 `SUPERSEDED` / 已终止 `TERMINATED` |
| 公告 | 草稿 `0` → 已发布 `1` |
| 短信发送 | 成功 `0` / 失败 `1` |

身份证识别的“正常、正反面颠倒、非身份证、模糊、反光过曝、过暗”等属于一次识别结果，不是按顺序流转的状态。

## 15. 专题说明

### 15.1 免培训报名

免培不是“培训学时为0的普通班级”，而是一条独立报名分支。

```text
考生选择免培类型和考试中心
  → 后端校验工种是否允许该免培类型
  → 校验免培最低学历
  → 部分住建证书调用国家平台核验
  → 生成人员、身份证、工作和免培报名记录
  → 直接生成考试资格申请
  → 市级、省级两级审批
  → 进入普通考试报名、缴费、考试和发证链路
```

主要规则：

- 人员来源标记为 `2`，表示免培报名；
- 免培资格和初训/复训类型从报名记录关联的项目取得，不依赖班级；
- 当前工种必须配置允许的免培类型；
- 学历低于该工种的免培最低学历时不能报名；
- 住建电工、住建焊工会核验有效证书；
- 免培不进入普通申请表材料快照流程；
- APP创建的免培申请直接进入待市局审批；机构端创建的记录可以先停留在待报审；
- 已审批通过或正在等待省厅审批的免培资料不能修改；修改后重新回到待市局审批。

### 15.2 省外报考

省外报考绕过本省普通培训班，先做“报考资料审核”。

```text
考生保存草稿
  → 提交省外报考申请
  → 监管端审核
  → 审核通过后生成人员快照
  → 生成考试报名资格
  → 进入考试报名、缴费、考试和成绩链路
```

状态为：草稿 `0` → 审核中 `1` → 审核通过 `2` 或审核不通过 `3`。

主要规则：

- 只有草稿或审核不通过状态可以继续保存、修改和再次提交；
- 只有审核中状态可以由监管人员审核；
- 审核通过后，后端先保存一份省外人员快照，再复用普通考试报名链路；
- 省外来源标记为 `1`；
- 当前国家平台约考定时补推明确排除省外人员快照，需要确认省外数据采用哪条外部同步方式。

### 15.3 复训和换证

复训和换证依赖旧证，不能当成一次完全独立的初次取证。

```text
选择复训项目
  → 查询并关联旧证
  → 完成复训及考试
  → 生成待发证记录
  → 校验旧证有效期结束日期
  → 到达“有效期结束前60天”窗口
  → 才允许申请/推送新证
```

主要规则：

- `projectType = 2` 表示复训；
- 复训证书必须关联旧证；
- 旧证有效期结束日期缺失时不能推送；
- 当前代码规定：从旧证有效期结束前60天开始，才允许申请/推送复训证书；
- 系统每天扫描未推送的复训证书，补齐旧证有效期结束日期；
- 选择旧证时会排除当前正在处理的新证，避免把新证错误当成自己的旧证。

### 15.4 报名申请表更正

当前代码处理的是“审核通过后的报名申请表更正”，不是任何时候都能修改个人资料。

允许更正的基础条件：

- 报名记录存在且属于当前机构；
- 报名记录没有被剔除；
- 培训报名已经审核通过；
- 考试资格没有审批通过，也不处于市局或省厅审批中；
- 尚未生成考试报名、考试实例或缴费信息；
- 国家平台考生信息不是已推送或推送中。

更正状态：

```text
无更正记录 → 更正中(OPEN) → 已完成(COMPLETED)
```

申请表正在签署或已经签完时，需要先撤销申请表；只有未发起、失败、已撤销状态可以直接修改。考试申请正在审批时必须先撤回，考试申请已经通过后不能走普通更正。

### 15.5 继续教育

当前继续教育模块主要服务于考务人员管理，不是普通考生的复训报名。

主要规则：

- 继续教育记录保存在 `exam_continuing_education`；
- 记录通过 `staffId` 关联考务人员；
- 当前查询逻辑先检查指定考务人员是否存在继续教育记录；
- 如果该人员存在记录，则返回全部继续教育记录；不存在则返回空列表。

最后一条查询规则比较特殊，可能是页面展示需求，也可能是实现遗留，建议业务确认“为什么查一个人却返回所有人的记录”。

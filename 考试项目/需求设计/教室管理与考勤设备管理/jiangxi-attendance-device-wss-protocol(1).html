1. 快速接入与传输矩阵

本文档只定义设备主动连入平台的 WSS 协议。设备侧先拿到 deviceId、accessKey、secretKey，连上联调地址后立即发 AUTH，认证成功后再进入心跳、状态和考勤上报。

联调地址仅用于联调与验收，生产地址由平台单独签发。设备不得经厂商云或第三方中转考勤数据。

快速接入检查

  1. 确认设备时间已对齐到 Asia/Shanghai，并按 yyyy-MM-dd HH:mm:ss 输出。
  2. 确认 TLS 1.2+、证书链和主机名校验均已启用。
  3. 确认联调地址可连通，单条消息不超过 2 MiB，图片解码后不超过 1 MiB。
  4. 确认认证窗口为 ±300 秒，nonce 复用窗口为 600 秒。
  5. 确认心跳 30 秒一次，90 秒无心跳或业务消息即视为离线。
  6. 确认业务处理端到端超时按 5 秒控制，失败时不得紧密重试。
项目 规范值 补充说明 方向
协议 WSS over TLS 必须启用 TLS 1.2+，证书链与主机名校验 MUST 开启 双向
编码 JSON / UTF-8 禁止以非 UTF-8 编码发送 双向
时区 Asia/Shanghai 时间戳必须是本地时间，不带时区后缀 双向
时间格式 yyyy-MM-dd HH:mm:ss 精确到秒 双向
单条消息大小 ≤ 2 MiB 按 UTF-8 字节数计 双向
照片解码大小 ≤ 1 MiB 仅 JPEG / PNG；支持 raw Base64 或 data URI 上行考勤
心跳 30 秒一次 任意业务消息也计入活动 设备 -> 平台
离线阈值 90 秒 90 秒无活动即离线 平台判定
认证窗口 ±300 秒 超窗直接失败并关闭连接 AUTH
Nonce TTL / 复用窗口 600 秒 单次使用，禁止重放 AUTH
业务处理超时 5 秒 超时属于可重试故障；客户端不得紧密循环重发 平台处理

3. 通用消息包

所有消息都使用统一外层包。设备发给平台的业务消息和平台回给设备的 ACK / ERROR 都沿用同一外层结构。

约束要点：payload MUST 是非空对象；未知字段将被忽略或丢弃；每次发送尝试都必须生成新的 messageId；同一考勤事件的 recordId 在设备内必须保持稳定且唯一。
字段 类型 约束 方向
messageId String 设备侧每次发送尝试都必须是新值；同设备内不得重复。平台回包应尽量回显；对不可关联的非法 JSON，messageId MAY 为 null。 双向
messageType String 设备上行仅允许 AUTH、HEARTBEAT、DEVICE_STATUS、ATTENDANCE_RECORD。平台下行仅允许 AUTH_ACK、HEARTBEAT_ACK、DEVICE_STATUS_ACK、ATTENDANCE_ACK、ERROR。设备不得主动发送 ACK / ERROR。 双向
deviceId String 必须与平台注册设备一致；认证成功后绑定到会话。 双向
timestamp String 必须使用 yyyy-MM-dd HH:mm:ss，时区为 Asia/Shanghai。 双向
payload Object MUST 非空对象；未知字段忽略/丢弃；文档未列明字段不形成兼容承诺。 双向

4. AUTH 认证

设备建立连接后必须先发 AUTH。平台按设备ID、接入密钥、时间戳、随机数和签名完成认证；未认证连接不得发送考勤业务。

字段 类型 规范值 / 约束 补充说明
accessKey String 必填，由平台线下发放 不可明文写入日志
nonce String 必填，单次使用，600 秒内不得复用 重放即失败
signature String HMAC-SHA256，结果为 64 位十六进制字符串，建议小写，输入大小写不敏感 严格 hex 解析
firmwareVersion String 可选 仅作透传，不参与签名串
认证签名串必须精确拼接为 deviceId + timestamp + nonce，中间无任何分隔符。设备端 secret 使用 UTF-8 作为 HMAC 密钥，平台验签采用常量时间比较。

认证测试向量

验证向量：deviceId DEV-001、timestamp 2026-07-14 10:15:30、nonce nonce-001、secretKey secret-001 的期望签名为 0a7742ae07d3b95fbbd78acfab5f1bc6fc1a6958b7922f350fadddd4e4432864。

accessKey / secretKey 的签发、绑定、失效和重配都在平台侧线下完成，不属于线上报文的一部分。

5. HEARTBEAT

心跳用于维持在线态。设备认证成功后每 30 秒发送一次心跳；任何业务消息也会被平台视为活动，不必额外补发心跳。

字段 类型 规范值 / 约束 补充说明
status String 可选；如上报，仅允许 ONLINE、OFFLINE、ABNORMAL 不接受中文值、历史文本或其他别名
localRecordCount Integer 当前可选；建议上报本地待传记录数 便于平台估算积压量

6. DEVICE_STATUS

设备状态消息用于上报启动、停机、故障、恢复、存储不足和摄像头异常等事件。状态字段和事件字段都必须明确；描述字段可选。

字段 类型 规范值 / 约束 补充说明
status String 必填；仅允许 ONLINE、OFFLINE、ABNORMAL 不接受中文值、历史文本或其他别名
event String 必填，枚举为 STARTUP、SHUTDOWN、FAULT、RECOVERY、STORAGE_LOW、CAMERA_ERROR 不接受中文值、历史文本或其他别名
description String 可选；用于补充设备自检、告警或恢复说明 不要放入密钥、Base64 或个人隐私数据

7. ATTENDANCE_RECORD

考勤记录是核心业务消息。平台收到后先做协议校验、签名/幂等/照片校验，再向上游业务层投递。ATTENDANCE_ACK code=0 只代表原始报文已被平台 durable 接收，不代表最终出勤匹配已经完成。

字段 类型 规范值 / 长度 / 约束 补充说明
recordId String 必填，≤ 64；同一设备内唯一；同一考勤事件重试时必须保持不变 平台按 (deviceId, recordId) 幂等
deviceName String 必填，≤ 64 用于审计和排障，不作为主键
personName String 必填，≤ 64 应与证件姓名一致
idCard String 必填，≤ 32 身份证号或平台认可的证件标识
punchTime String 必填，精确到秒，格式 yyyy-MM-dd HH:mm:ss 实际打卡时间，补传时不得改写
createTime String 必填，精确到秒，格式 yyyy-MM-dd HH:mm:ss 设备生成记录时间
punchType String 规范码为 IN / OUT 仅接受英文规范码，不接受中文值或别名
verifyType String 必填；仅允许 FACE / FINGERPRINT / CARD / OTHER 仅接受英文规范码，不接受中文值或别名
verifyResult String 规范码为 PASS / FAIL 仅接受英文规范码，不接受中文值或别名
photoBase64 String 可传 raw Base64 或 data URI；仅 JPEG / PNG；解码后 ≤ 1 MiB 当 verifyType=FACE 且 verifyResult=PASS 时必填
所有协议枚举字段只接受英文规范码：IN / OUT、FACE / FINGERPRINT / CARD / OTHER、PASS / FAIL。不接受中文值、历史文本或其他别名；FACE + PASS 必须携带照片。

photoBase64 支持 raw Base64 或 data:image/jpeg;base64, / data:image/png;base64, 前缀；平台会先解码、再校验格式和大小。成功 ACK 只代表原始报文已被平台接受，不代表最终 attendance matching 完成。

8. 平台回包形状与示例

平台发送给设备的终端消息沿用统一外层包，固定形状如下：{messageId,messageType,deviceId,timestamp,payload:{code,message,recordId?,serverTime}}。recordId 仅出现在考勤响应中；serverTime 应在所有 ACK / ERROR 中返回。

当请求 JSON 不可关联或无法解析时，平台仍然返回 ERROR；此时 messageId MAY 为 null。正常可关联请求则应回显原 messageId。
ACK / ERROR 只能由平台发给设备。设备如果把 AUTH_ACK、HEARTBEAT_ACK、DEVICE_STATUS_ACK、ATTENDANCE_ACK、ERROR 当作上行消息发送，平台应判定为无效报文。

9. 错误码矩阵

下面的错误码覆盖当前协议约束。除 SERVER_BUSY 外，其余 fatal 错误都应关闭当前连接。SERVER_BUSY 可能因为超时、过载或停机而关闭连接，设备端必须同时支持“连接保留”和“连接关闭”两种结果。

code 含义 重试动作 是否关闭连接
0 成功 无需重试；按业务继续处理 否
AUTH_FAILED 认证失败 检查 deviceId、accessKey、nonce、时间戳和签名；修正后重新认证 是
DEVICE_DISABLED 设备已停用 先恢复设备状态再重新连接 是
INVALID_MESSAGE 消息格式错误 修正 JSON / envelope / 字段结构后再发 是
INVALID_SIGNATURE 签名错误 检查 canonical string 与 secretKey 是
TIME_EXPIRED 时间戳超窗 校准设备时间后重新认证 是
RECORD_INVALID 考勤记录不合法或冲突 修正内容或人工处理；同一 (deviceId,recordId) 的冲突版本不得再重试 是
SERVER_BUSY 平台繁忙 至少等待 10 秒后再试；若连接已关闭则重新建连 可能关闭
所有 fatal 错误都属于“当前尝试失败”。其中 SERVER_BUSY 既可能是可重试拥塞，也可能因超时、过载或关停被主动关闭连接；设备不得做紧密循环重发。

10. 幂等、重试、离线缓存

规则 要求 说明
messageId 每次发送尝试必须生成新值 平台按 (deviceId,messageId) 做请求级去重
recordId 同一考勤事件重试时必须保持不变 平台按 (deviceId,recordId) 做记录级去重
重复内容 完全相同的 payload 和 photo digest 重发可接受 仍按幂等成功处理
冲突内容 同一 recordId 但 payload / photo digest 不一致时不可重试 返回 RECORD_INVALID，并视为安全事件
离线缓存 必须同时满足 7 天和 10000 条记录 两者都要满足，不能只满足其中一个
删除时机 只在收到 code=0 后删除本地原始记录 未确认或失败记录必须保留
补传顺序 按 punchTime 的时间顺序发送 不要按入库顺序打乱原始时序
重试间隔 重试间隔 MUST ≥ 10 秒 设备厂商自行定义退避算法，但不得 tight loop

平台按业务逻辑先接收 raw report，再异步做最终 attendance / matching。设备收到 ACK 后可以删本地记录；若未收到 ACK，必须保留并按上表重试。

11. 安全、日志与隐私

  • 生产流量 MUST 走 WSS/TLS，经网关终止后再进入平台运行环境。
  • 设备凭证、签名、nonce、accessKey、secretKey 不得写入普通日志、错误栈或可公开导出的调试信息。
  • photoBase64、原始签名和明文密钥必须从业务日志中剔除；如需追踪，只保留 SHA-256 摘要、对象键和必要审计字段。
  • 未知字段默认丢弃，不作为存证或下游透传的稳定契约。
  • 对 RECORD_INVALID、签名不一致和同一 recordId 的冲突重发，平台应记录安全审计事件。
  • 设备厂商不得用云中转、转存、二次加工或转卖考勤数据。
当前实现的 raw JSON 只用于规范化审计快照，不应包含 Base64 照片、密钥、签名或未白名单字段。外部文档只承诺协议行为，不暴露内部存储结构。

12. 上线、凭证与运行状态

凭证签发 平台按设备维度线下签发 deviceId、accessKey、secretKey，并明确绑定教室/机构范围。
变更规则 设备更换、迁移、停用、IP 变更或重置密钥时，必须重新完成联调与授权更新。
运行状态 平台侧应能区分 ONLINE、OFFLINE、ABNORMAL 与未认证状态，用于现场排障和告警。

设备侧操作建议

  • 连接失败先检查证书、时间、DNS、端口和网关放行。
  • 认证失败先检查 deviceId、accessKey、secretKey、签名串和时间窗。
  • 业务失败先确认 messageId / recordId 是否唯一，照片是否可解码，字段是否超长。
  • 离线恢复后优先补传最早的未确认记录，再继续实时上报。

14. 排障清单

  1. 先看连接是否走了正确的 WSS 地址、证书和主机名。
  2. 再看时间戳是否超窗，设备时钟是否漂移。
  3. 再看签名串是否严格等于 deviceId + timestamp + nonce。
  4. 再看 messageId 是否每次重试都换新，recordId 是否保持稳定。
  5. 再看 photoBase64 是否是 JPEG / PNG、是否超过 1 MiB、是否缺少 FACE + PASS 场景下的必填照片。
  6. 再看设备是否在 SERVER_BUSY 后做了紧密循环重发。
  7. 最后检查平台是否返回了 RECORD_INVALID，这通常意味着同 recordId 的内容发生冲突。

15. 规范码与变更

所有协议枚举字段只接受本文列出的英文规范码，不提供中文值、历史文本或其他别名兼容。

  • 考勤方向仅允许 IN / OUT，核验方式仅允许 FACE / FINGERPRINT / CARD / OTHER，核验结果仅允许 PASS / FAIL。
  • 状态值仅允许 ONLINE / OFFLINE / ABNORMAL，状态事件仅允许 STARTUP / SHUTDOWN / FAULT / RECOVERY / STORAGE_LOW / CAMERA_ERROR。
  • 如果后续协议扩展字段或状态码，只有本文档与平台联调确认后的值才是外部合同。
  • 当业务要求变化时，设备厂商与平台测试方必须同步更新需求文档、实施文档和验收清单。

本文档仅描述接口协议与外部行为，不公开平台内部实现、表结构或中间件选择。

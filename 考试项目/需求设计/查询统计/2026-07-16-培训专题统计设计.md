# 培训专题统计设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 设计日期 | 2026-07-16 |
| 适用版本 | 查询统计与数据统计分析驾驶舱 V1.3 |
| 现有基线 | `查询统计与数据统计分析驾驶舱PRD.md` V1.2、当前 Vue 2/Vue 3 数据总览页面 |
| 前端范围 | `监管机构` Vue 2、`监管机构v3.0` Vue 3 |
| 后端范围 | `spt/spt-train/spe-exam-biz` |
| 数据原则 | 使用真实业务数据，不新增数据库表，不使用生产模拟数据 |

## 2. 目标与范围

在监管端增加“培训专题统计”，覆盖以下六个专题：

1. 培训计划统计。
2. 培训人员统计。
3. 培训机构统计。
4. 授课老师统计。
5. 培训通过情况统计。
6. 培训机构处罚统计。

同时提供已归档培训资料查询，以及一次生成六个工作表的统计报表导出。

### 2.1 与现有数据总览的关系

现有数据总览继续完整保留以下内容，任何新增功能不得替换或删除它们：

- 总览。
- 培训分析。
- 考试分析。
- 证书分析。
- 考务人员。
- 缴费分析。

现有数据总览的“培训分析”区域增加一条紧凑的“培训专题概览”，展示培训计划、培训人员、培训机构、实际授课老师、培训合格率、机构违规次数六项指标，并提供“查看培训专题统计”入口。

新增独立菜单与页面：`查询统计 > 培训专题统计`。页面路由统一为 `/dataStatistics/trainingTopic/index`，两套前端分别放在：

- `监管机构/src/views/dataStatistics/trainingTopic/index.vue`
- `监管机构v3.0/src/views/dataStatistics/trainingTopic/index.vue`

### 2.2 本期不做

- 不在新增页面提供单位或培训机构查询条件。
- 不把六个新增专题直接铺到原数据总览页面。
- 不新增数据库表。
- 不增加自动刷新或统计缓存。
- 不导出个人姓名、身份证号等培训人员明细。
- 不提供单个专题单独导出。

## 3. 页面结构

### 3.1 数据总览接入

“培训专题概览”放在现有“培训分析”区域末尾，使用当前数据总览的地市和日期条件。该区域单独加载和报错，不影响原培训分析内容。

六项概览指标口径：

| 指标 | 口径 |
| --- | --- |
| 培训计划 | 计划日期与查询日期有交集的培训计划去重数 |
| 培训人员 | 范围内正式入班人员按 `trainee_signup_id` 去重数 |
| 培训机构 | 授权区域内全部启用机构数，不受日期条件影响 |
| 实际授课老师 | 范围内课程安排中实际出现的老师去重数 |
| 培训合格率 | `training_qualify_status = '1'` 的正式入班人员数 / 正式入班人员数 |
| 机构违规次数 | 数据总览结束日期所属年度的 `violation_count` 合计 |

### 3.2 培训专题统计页

页面顶部只显示标题、一键导出按钮，以及“统计分析 / 归档资料”两个视图标签，不放公共查询条件。

“统计分析”视图使用纵向驾驶舱布局，六个专题全部展开。标题下方设置粘性锚点导航，点击后滚动到对应专题。每个专题依次包含：

1. 专题标题与当前已查询条件摘要。
2. 本专题筛选栏。
3. 指标卡。
4. 图表。
5. 服务端分页明细。

视觉样式继续使用现有监管系统的蓝色主色、浅灰页面背景、白色内容面板、细分隔线和紧凑表格，不显示 `01`、`02` 等标题序号。

### 3.3 独立筛选

培训计划、培训人员、培训机构、授课老师、培训通过情况五个专题分别提供：

| 筛选项 | 控件 | 默认值 |
| --- | --- | --- |
| 培训计划 | 计划名称关键字输入 | 空 |
| 人员分类 | 系统字典下拉 | 全部 |
| 地市 | 授权地市下拉 | 全部授权地市 |
| 计划日期 | 日期范围选择器 | 当前年度 1 月 1 日至当天 |

培训机构处罚专题只提供：

| 筛选项 | 控件 | 默认值 |
| --- | --- | --- |
| 地市 | 授权地市下拉 | 全部授权地市 |
| 评估年度 | 年份选择器 | 当前年度 |

交互规则：

- 页面首次进入时六个专题使用各自默认条件并行查询。
- 点击某个专题的“查询”只刷新该专题，并将其明细重置到第 1 页。
- 点击“重置”恢复该专题默认条件，并立即重新查询该专题。
- 切换分页只请求当前专题。
- 各专题独立维护表单值、最后成功查询条件、分页、加载、错误和请求序号。
- 快速连续查询时丢弃迟到响应，旧响应不得覆盖新结果。
- 人员分类名称使用系统字典，不在前端维护中文映射。

### 3.4 归档资料

“归档资料”视图首次打开时才加载。它拥有自己的培训计划、人员分类、地市和计划日期筛选，不继承六个专题的筛选状态。

列表一行对应一个已归档培训班，使用服务端分页，字段为：

| 字段 | 说明 |
| --- | --- |
| 培训计划 | 培训计划名称 |
| 班级名称 | 已归档班级名称 |
| 培训机构 | 计划所属培训机构 |
| 人员分类 | `QualificationRootCategoryEnum` 或系统字典名称 |
| 地市 | 培训机构所属地市，上卷到地市级 |
| 计划日期 | 计划开始、结束日期 |
| 参训人数 | 正式入班人员去重数 |
| 归档时间 | `tr_training_archive.archive_time` |
| 操作 | 查看资料、下载当前培训班档案 |

查看资料为只读详情，展示培训班信息、报审信息和学员名单资料。本期只提供单个培训班档案下载，不增加跨培训班批量打包下载。

## 4. 六个专题内容

### 4.1 培训计划统计

指标：计划总数、拟培训人数、已报备计划、进行中计划、已完成计划。

图表：计划状态分布、按计划开始月份统计的计划数量趋势。

明细一行一个培训计划，字段为：培训计划、培训机构、人员分类、培训方式、计划日期、拟培训人数、实际参训人数、计划状态。

计划日期筛选采用区间相交口径：`计划开始日期 <= 查询结束日期` 且 `计划结束日期 >= 查询开始日期`。已报备使用 `report_status = 1`；进行中使用 `start_date <= 当前日期 <= end_date`；已完成使用 `end_date < 当前日期`。计划状态分布使用现有上报状态和上述日期规则，不从班级状态反推计划状态。

### 4.2 培训人员统计

指标：参训人数、培训合格人数、培训不合格人数、待判定人数、覆盖计划数。

图表：人员分类分布、按计划开始月份统计的参训人数趋势。

明细按“培训计划 + 人员分类”汇总，字段为：培训计划、人员分类、参训人数、合格人数、不合格人数、待判定人数、合格率。

参训人员限定正式入班记录并按 `trainee_signup_id` 去重。`training_qualify_status = '1'` 为合格，`'0'` 为不合格，空值或其他未完成判定的值为待判定。合格率 = 合格人数 / 参训人数；分母为 0 时返回 `null`。

### 4.3 培训机构统计

指标：启用培训机构、有计划机构、培训计划数、参训人数、平均合格率。

图表：按参训人数统计的机构培训规模 TOP 10、存在判定结果的机构合格率 TOP 10。

明细一行一个培训机构，字段为：培训机构、地市、计划数、拟培训人数、参训人数、合格人数、合格率。

“启用培训机构”只响应地市条件，统计授权区域内全部启用机构，不受培训计划、人员分类和计划日期影响；其余指标响应本专题全部筛选条件。机构合格率 = 机构培训合格人数 / 机构参训人数。

### 4.4 授课老师统计

指标：实际授课老师、专职老师、兼职老师、授课课次、授课时长。

图表：实际授课老师专兼职占比、老师授课时长 TOP 10。

明细一行一个实际授课老师，字段为：老师姓名、培训机构、专兼职类型、授课类型、授课计划数、授课课次、授课时长。

老师必须在查询范围内的 `tr_curriculum` 课程安排中实际出现。专兼职类型和授课类型使用现有老师字典字段；授课计划数按计划去重，授课课次按有效课程安排计数，授课时长按课程安排的实际时长汇总。

### 4.5 培训通过情况统计

指标：参训人数、取得学时证明人数、培训合格人数、培训不合格人数、培训合格率。

图表：按计划开始月份统计的培训合格率趋势、三类人员培训合格率对比。

明细按“培训计划 + 培训机构 + 人员分类”汇总，字段为：培训计划、培训机构、人员分类、参训人数、取得学时证明人数、培训合格人数、合格率。

取得学时证明人数按满足现有学时证明生成条件的正式入班人员去重。培训合格人数使用 `tr_trainee_signup.training_qualify_status = '1'`。培训合格率 = 培训合格人数 / 参训人数；分母为 0 时返回 `null`。

### 4.6 培训机构处罚统计

数据来源为 `tr_institution_evaluation.violation_count`。

指标：参评机构、违规次数、涉及违规机构、不合格机构、机构平均分。

图表：机构违规次数 TOP 10、评估等级分布。

明细按“培训机构 + 评估年度”汇总，字段为：培训机构、地市、评估年度、评估等级、平均分、违规次数、评估状态。

处罚专题不响应培训计划、人员分类和计划日期。违规次数为筛选范围内 `violation_count` 合计，涉及违规机构为违规次数大于 0 的机构去重数；评估等级、分数和状态使用机构年度评估现有字段和字典。

## 5. 公共数据口径

| 口径 | 规则 |
| --- | --- |
| 删除标识 | 业务表存在 `del_flag` 时统一过滤 `del_flag = '0'` |
| 数据范围 | 服务端根据当前监管用户授权区域强制收窄，地市用户不能通过参数扩大范围 |
| 租户过滤 | 不使用培训机构表 `tr_institution.tenant_id` 过滤监管统计数据 |
| 地域粒度 | 区县数据上卷到所属地市，地市筛选和展示只精确到地市 |
| 时间边界 | 开始日期包含当天；结束日期包含当天，SQL 使用结束日期次日零点作为排他上界 |
| 人员分类 | 使用 `QualificationRootCategoryEnum` 或系统字典，不维护中文 Map |
| 人数去重 | 培训人员优先按 `trainee_signup_id` 去重，老师按 `teacher_id` 去重 |
| 比率 | 返回 0 到 100、保留 1 位；分母为 0 返回 `null`，前端显示 `--` |
| 空数据 | 数量真实零值显示 `0`；无比率显示 `--`；图表和表格使用系统空状态 |

统计查询覆盖范围内全部有效业务数据，不额外限定培训机构租户。

## 6. 后端设计

### 6.1 模块与分层

所有新增后端代码位于 `spe-exam-biz`，不新增数据库表。新增以下职责边界：

- `TrainingStatisticsController`：参数绑定、权限入口、文件响应。
- `TrainingStatisticsService`：日期规范化、区域收窄、指标组装、分页和导出编排。
- `TrainingStatisticsMapper` 与 XML：聚合查询和明细分页查询。
- 模块内查询 DTO、响应 VO 和导出行模型：不修改 `spe-exam-api`。

复杂区域上卷、人数去重、状态兼容和导出分片逻辑应添加简洁注释；显而易见的字段赋值不添加重复注释。

### 6.2 接口

| 方法与路径 | 用途 |
| --- | --- |
| `GET /training-statistics/summary` | 数据总览中的六项专题概览 |
| `GET /training-statistics/plan` | 培训计划指标、图表和分页明细 |
| `GET /training-statistics/person` | 培训人员指标、图表和分页明细 |
| `GET /training-statistics/institution` | 培训机构指标、排行和分页明细 |
| `GET /training-statistics/teacher` | 授课老师指标、排行和分页明细 |
| `GET /training-statistics/pass` | 培训通过指标、图表和分页明细 |
| `GET /training-statistics/penalty` | 机构处罚指标、图表和分页明细 |
| `GET /training-statistics/archive` | 已归档培训班分页列表 |
| `POST /training-statistics/export` | 生成六工作表 Excel |

前五个专题、通过情况和归档资料使用：`planKeyword`、`personType`、`areaId`、`startDate`、`endDate`、`current`、`size`。处罚专题使用：`areaId`、`assessmentYear`、`current`、`size`。

分页默认第 1 页、每页 10 条，允许 10、20、50、100，服务端将其他值限制到合法范围。

每个专题接口返回三个独立部分：指标、图表数据、分页明细。分页变化时允许前端仍调用同一接口，后端必须保证指标和图表口径与明细筛选一致。

### 6.3 导出请求

导出采用 POST JSON，结构包含六组最后成功查询条件：

```json
{
  "planQuery": {},
  "personQuery": {},
  "institutionQuery": {},
  "teacherQuery": {},
  "passQuery": {},
  "penaltyQuery": {}
}
```

后端忽略各组分页参数，使用流式写入生成完整结果。任一工作表生成失败时整个请求失败，不返回部分工作簿。

文件名为 `培训专题统计_YYYYMMDDHHmmss.xlsx`，包含且仅包含以下六个工作表：

| 工作表 | 每行粒度 | 字段 |
| --- | --- | --- |
| 培训计划统计 | 培训计划 | 计划名称、培训机构、人员分类、培训方式、计划日期、拟培训人数、实际参训人数、计划状态 |
| 培训人员统计 | 计划 + 人员分类 | 培训计划、人员分类、参训人数、合格人数、不合格人数、待判定人数、合格率 |
| 培训机构统计 | 培训机构 | 培训机构、地市、计划数、拟培训人数、参训人数、合格人数、合格率 |
| 授课老师统计 | 老师 | 老师姓名、培训机构、专兼职类型、授课类型、授课计划数、授课课次、授课时长 |
| 培训通过情况 | 计划 + 机构 + 人员分类 | 培训计划、培训机构、人员分类、参训人数、取得学时证明人数、培训合格人数、合格率 |
| 培训机构处罚 | 机构 + 评估年度 | 培训机构、地市、评估年度、评估等级、平均分、违规次数、评估状态 |

每个工作表顶部记录该专题实际使用的筛选条件，数据区字段可筛选，不输出个人敏感信息。

## 7. 前端设计

### 7.1 双版本等价实现

Vue 2 使用 Options API 和项目现有请求、字典、表格、分页及 ECharts 封装；Vue 3 使用 Composition API 和现有对应封装。两套页面的标题、筛选项、指标、图表、表格字段、空状态和错误状态必须一致。

新增 API 模块、专题筛选组件、指标与图表面板、分页表格以及格式化辅助模块。公共组件只抽取确实重复的筛选、加载和分页行为，六个专题的业务字段保持各自清晰。

### 7.2 状态与请求

- 六个专题首次并行加载，使用 `Promise.allSettled` 等价策略隔离失败。
- 每个专题保存 `draftFilters` 和 `committedFilters`；点击查询成功后更新最后成功条件。
- 查询、重置、分页和重试只修改当前专题状态。
- 每个专题维护递增请求序号，只接收最新请求响应。
- 图表监听容器尺寸变化并执行 `resize`，组件销毁时释放实例和监听器。
- 归档资料首次进入时加载，之后保留其查询和分页状态。
- 一键导出使用六个专题的最后成功查询条件；用户只修改输入但未点击查询时，导出结果与当前页面已展示数据保持一致。
- 导出期间按钮禁用并显示加载状态，失败时显示系统错误提示。

### 7.3 表格与响应式

- 表头和字段统一居中。
- 表格内容保留左右内边距，分页右侧保留间距。
- 固定格式区域设置稳定高度或最小高度，加载、空状态和数据切换时不产生明显跳动。
- 窄屏桌面允许筛选项换行和表格内部横向滚动，不隐藏统计字段。

## 8. 错误与边界处理

| 场景 | 行为 |
| --- | --- |
| 单专题加载失败 | 仅当前专题显示错误和重试按钮，其他专题保持可用 |
| 无指标值 | 数量显示 `0`，无分母比率显示 `--` |
| 无图表或表格数据 | 显示系统“暂无数据”状态 |
| 连续查询 | 丢弃旧请求迟到响应 |
| 日期非法 | 前端阻止开始日期晚于结束日期，后端再次校验并返回明确错误 |
| 区域越权 | 后端按授权范围收窄，不信任客户端区域参数 |
| 导出失败 | 不下载损坏或部分文件，恢复按钮并显示失败提示 |
| 档案文件缺失 | 当前档案显示不可下载提示，不影响列表其他行 |

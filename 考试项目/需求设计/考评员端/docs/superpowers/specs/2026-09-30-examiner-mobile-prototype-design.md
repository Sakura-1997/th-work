# 考务人员移动端原型设计说明

## 1. 目标

为考试系统设计一套考务人员使用的移动端可点击原型，服务对象包含考评员、监考员和巡考员。原型帮助当前登录人员快速处理分派给自己的考务任务，并查看自己的历史履职情况。

本次只做轻量单页原型，不接真实接口、不接登录、不进入实际开考和评分流程。原型使用本地模拟数据，通过点击完成核心流程验证。由于本次已确认的详细操作主要来自考评员场景，原型默认使用“考评员”作为演示账号；监考员和巡考员只纳入统一框架，不凭空增加未确认的角色专属操作。

## 2. 已确认范围

- 原型放在 `E:\泰豪工作目录\考试项目\需求设计\考评员端`；目录名沿用已有约定，页面和产品名称统一使用“考务人员端”。
- 不使用原来的“实操考试app”，本原型为独立项目。
- 服务对象包含考评员、监考员和巡考员；三类人员共用同一套端，当前登录人员只看到分派给自己的考务任务。
- 角色由登录账号和权限决定，页面不提供考评员、监考员、巡考员之间的切换入口。
- 原型默认使用考评员账号演示；监考员和巡考员的专属任务内容、操作规则待后续需求确认后补充。
- 使用轻量单页实现，不引入复杂项目结构。
- 底部导航包含四个入口：`待办`、`任务`、`分析`、`我的`；其中任务在产品文案中称为“考务任务”，分析表示当前人员的履职分析。
- 不做“行为预警”页面。
- “分析”表示当前人员的历史履职情况、分数统计和履职表现；本次原型默认展示考评员的历史考评数据。
- 当前人员可以查看自己的分析；未来监管端可在“考评员管理 → 详情”中增加入口复用考评员分析内容，本次不实现监管端。
- 个人中心只展示：姓名、手机号、所属考点、累计考评次数、履职评分。由于本次原型默认使用考评员账号，字段沿用已确认的考评员口径；其他人员类型接入时再按角色确认字段名称。
- 任务未接受前不能查看考生名单。
- 任务接受后可以查看考生名单。
- 考评员可以接受或拒绝考评任务。
- 拒绝任务时需要选择拒绝原因。
- 考评员接受任务后，在考试开始前可以撤销接受；撤销时需要填写原因，任务回到待处理状态。
- 不展示“开考”按钮，也不实现开考流程。

## 3. 页面和交互

### 3.1 待办

待办首页用两个标签页承载任务，作用是让当前考务人员打开应用后马上看到"近期要参加的任务"和"还没有响应的任务"。两个标签页里的任务都只负责提醒和快速进入详情，具体操作统一放在任务详情页完成。

展示内容：

- 顶部为分段式标签页：`待考试任务`和`待处理考试`，默认进入`待考试任务`；两个标签页的数量角标直接显示在标签上，底部导航不再显示角标。
- `待考试任务`：已经接受，且当前时间早于具体考试开始时间的任务。
- `待处理考试`：还没有接受或拒绝的任务。
- 当前标签页展示对应的任务卡片，卡片展示考试名称、日期时间、考点、科目和当前状态。
- 页面不使用整版蓝色头部；当前登录人员身份在"我的"页面展示。

待办展示规则：

- `待考试任务`只显示状态为已接受，且当前时间早于该任务的考试开始时间的任务。
- `待处理考试`只显示状态为待响应的任务，不受考试日期影响，直到考评员接受或拒绝。
- 考试日期是具体的某一天，考试开始时间用于判断任务是否已经开始。例如当前时间为 `2026年9月30日 14:00` 时，考试开始时间为 `2026年9月30日 18:00` 的已接受任务仍显示在待考试任务中；考试开始时间为 `2026年9月30日 13:30` 的任务不再显示在待办中，但仍保留在任务中心历史中。
- 待处理考试中的任务点击后进入任务详情，在详情页接受或拒绝；不在待办卡片上直接处理。

点击两个标签页中的任务卡片都进入任务详情：待处理考试显示接受和拒绝操作；待考试任务显示任务信息和考生名单入口。

### 3.2 考务任务

考务任务页按状态查看当前人员被分派的任务：

- `待响应`：可以查看任务基本信息，并进入接受或拒绝操作。
- `已接受`：可以查看任务基本信息和考生名单。
- `已拒绝`：展示拒绝原因和处理结果。
- `已完成`：展示历史任务的基本结果。

任务详情的状态规则：

1. 待响应状态显示“接受任务”和“拒绝任务”两个操作。
2. 待响应状态只显示“接受后可查看考生名单”的提示，不显示名单内容。
3. 点击“接受任务”后，任务变为已接受，首页“待处理考试”数量减少，符合日期条件时进入“待考试任务”，并立即解锁“查看考生名单”。
4. 点击“拒绝任务”后弹出底部弹层，要求选择拒绝原因：`时间冲突`、`地点不便`、`临时有事`、`其他原因`。
5. 选择拒绝原因并确认后，任务变为已拒绝，记录拒绝原因，从首页“待处理考试”中移除，不能查看考生名单。
6. 已接受任务可以点击“查看考生名单”，进入名单弹层或详情视图；已接受任务不再显示接受或拒绝操作。
7. 考试开始前，已接受任务显示“撤销接受”操作；点击后弹出原因选择：`临时有事`、`时间冲突`、`其他原因`。
8. 确认撤销后，任务回到待响应状态，进入首页“待处理考试”，保留“已接受后撤销”的记录和撤销原因；撤销后可以重新接受任务。
9. 考试开始时间已到后，不再显示“撤销接受”操作；详情页仍可查看任务信息和已授权的考生名单。
10. 任何状态都不出现开考入口、开考按钮或评分入口。

### 3.3 分析

分析页展示当前人员的历史履职和统计；本次默认展示考评员个人的历史考评和分数统计，包括：

- 累计考评次数。
- 本月考评次数。
- 平均分。
- 通过率。
- 履职评分。
- 分数统计：最高分、最低分、平均分、合格人数、不合格人数。
- 月度考评趋势。
- 历史考评记录：考试名称、考点、日期、考生人数、平均分和通过率。分析页只展示最近三条预览，点击"更多"进入全部历史考评记录列表；列表页支持按考试名称模糊搜索、按具体日期筛选和一键重置，并显示符合条
件的记录数量，无结果时显示空态提示。

现有资料可以确认考试成绩包含分数和合格/不合格结果，但没有确认考评员成绩使用“优秀、良好、待改进”等分数区间。因此本原型不自行规定分数段，也不展示未经确认的等级标签。原型中的图表使用 CSS 或轻量 SVG/CSS 图形模拟，不接图表接口。统计数字和记录来自本地模拟数据，便于点击演示。

### 3.4 我的

只展示以下信息：

- 姓名。
- 手机号。
- 所属考点。
- 累计考评次数。
- 履职评分。

不增加身份证号、证书编号、擅长专业、通知设置和账号安全等未确认字段。

## 4. 视觉方向

采用“考试指挥台”风格：

- 深蓝色作为主色，传达稳定和可信赖。
- 暖黄色用于重点操作和待处理提示，突出“需要现在处理”的任务。
- 白色卡片承载信息，页面背景使用浅灰蓝色，降低长时间查看的疲劳感。
- 状态颜色固定：待响应使用暖黄色，已接受使用绿色，已拒绝使用灰色，已完成使用蓝色。
- 页面以手机宽度为主要展示尺寸，在电脑浏览器中提供居中的手机外框效果。
- 操作按钮采用大面积、易点击的设计；重要动作使用清晰的文字，不依赖图标猜意思。

## 5. 原型状态模型

任务状态只保留以下四种：

```text
待响应 ──接受──> 已接受 ──查看──> 考生名单
   │
   └─拒绝并填写原因──> 已拒绝

已接受且当前时间早于考试开始时间：显示在待考试任务
已接受且考试开始时间已到：只保留在任务中心历史中，不能撤销接受
已接受 ──考试开始前撤销并填写原因──> 待响应
待响应 ──重新接受──> 已接受（保留撤销记录）
已完成：仅用于历史任务展示，不提供新的业务操作
```

首页待办统计从任务状态和具体考试开始时间派生：

- 待考试任务数量 = 当前状态为已接受，且当前时间早于考试开始时间的任务数量。
- 待处理考试数量 = 当前状态为待响应的任务数量。
- 考试开始时间已到的已接受任务不再计入待办统计，但保留在任务中心历史中。
- 已拒绝任务保留在任务中心历史中，不计入待办统计。

## 6. 本地模拟数据

至少准备以下演示数据：

- 一条待响应任务，用于在任务中心演示接受和拒绝。
- 一条已接受任务，用于演示已解锁的考生名单。
- 一条当天尚未开始的已接受任务，用于演示待办展示和撤销接受。
- 一条未来日期的已接受任务，用于演示待办中的近期任务。
- 一条考试开始时间已到的已接受任务，用于演示待办过滤和撤销按钮隐藏，但仍保留在任务中心历史中。
- 一条已完成任务，用于展示历史任务。
- 一条已拒绝任务，用于展示拒绝原因。
- 三条以上历史考评记录，用于展示分析页的统计和趋势；记录总量应多于分析页预览条数，以支撑"更多"入口和名称 / 日期查询演示。
- 一组已接受任务的考生名单，包含姓名、证件号脱敏展示、考试科目和签到状态。

原型数据只保存在当前页面运行期间。刷新后可以恢复默认演示状态，不需要持久化。

## 7. 验收标准

- 打开原型即可看到待办首页，并能在四个底部入口之间切换。
- 待办首页包含“待考试任务”和“待处理考试”两个标签页，数量角标显示在标签上。
- “待考试任务”只显示已接受且尚未到考试开始时间的任务；考试开始后不再显示在待办中。
- “待处理考试”显示尚未接受或拒绝的任务。
- 两个标签页中的任务都能进入任务详情；待处理任务在详情页接受或拒绝，已接受任务在详情页查看任务信息和考生名单。
- 未接受任务时看不到考生名单，只看到解锁提示。
- 接受任务后能看到考生名单入口，并且首页统计同步变化。
- 拒绝任务时必须选择拒绝原因；确认后能在任务列表和详情中看到拒绝结果。
- 接受后可以在考试开始前撤销；撤销后回到“待处理考试”，填写的撤销原因和操作记录仍可查看。
- 考试开始后不能撤销接受。
- 分析页能看到历史考评记录、最高分、最低分、平均分、合格/不合格人数、通过率和履职评分；不自行定义优秀/良好等分数段。
- 我的页面只展示已确认的五类信息。
- 全部页面和文案不出现“行为预警”“开考”“开始考试”“评分操作”等本次排除内容。
- 页面在手机尺寸下可完整阅读和点击，电脑预览时保持居中手机外框。

## 8. 后续可扩展边界

真实项目阶段可把本原型拆成考务任务接口、任务状态接口、角色权限接口、考生名单接口和履职分析接口；监管端的考评员详情页可以直接复用考评员分析页的数据结构和展示逻辑。本次原型不提前加入这些接口和管理功能，也不提前定义监考员、巡考员的专属任务字段。

# 考务人员端 · 移动端原型

面向考评员、监考员、巡考员的考务任务处理原型。三类人员共用同一套端，角色由登录账号和权限决定，页面不提供角色切换入口；本原型默认使用“考评员”账号演示。

## 运行方式

- 直接双击 `index.html` 即可在浏览器中打开。
- 如需本地服务，可在本目录执行 `python -m http.server 4173`，再访问 `http://localhost:4173`。
- 电脑浏览器中以居中的手机外框展示；窗口宽度小于 540px（或手机浏览器）时自动去掉外框，占满全屏。
- 不安装任何依赖，不接真实接口，不接登录；数据只保存在当前页面运行期间，刷新即恢复默认演示状态。

## 演示约定

- 固定演示时间为 `2026-09-30 14:00`（见 `index.html` 中的 `demoNow`），用于稳定复现“当天未开始 / 当天已开始 / 未来任务”的边界状态。
- 演示账号：李卫平（考评员），所属考点：南昌一中考点。

## 页面结构

底部导航固定四项：

| 入口 | 内容 |
| ---- | ---- |
| 待办 | 待考试任务、待处理考试两个标签页切换，数量角标显示在标签上 |
| 任务 | 考务任务中心，按待响应 / 已接受 / 已拒绝 / 已完成筛选 |
| 分析 | 履职分析：累计/本月考评次数、平均分、通过率、履职评分、最高/最低分、合格/不合格人数、月度趋势、历史考评记录（最近三条预览，可进入全部记录列表并按名称、日期查询） |
| 我的 | 姓名、手机号、所属考点、累计考评次数、履职评分 |

## 任务状态

- `pending` 待响应：可接受或拒绝；接受前不显示考生名单，只显示“接受后可查看考生名单”提示。
- `accepted` 已接受：可查看任务信息和考生名单；考试开始前可撤销接受。
- `rejected` 已拒绝：保留拒绝原因和操作记录，不能查看考生名单。
- `completed` 已完成：仅作历史展示。

待办板块派生规则：

- 待考试任务 = 状态为已接受，且当前时间早于该任务具体考试开始时间。
- 待处理考试 = 状态为待响应。
- 考试开始时间已到的已接受任务不再计入待办，但保留在任务中心历史中。

## 手工验收路径

1. 打开原型，默认进入待办页，顶部为“待考试任务 / 待处理考试”两个标签页（数量角标在标签上，默认显示待考试任务），点击可切换；四个底部入口可切换，底部导航无角标。
2. 待考试任务中没有 9 月 30 日 13:30 开始的已接受任务（考试已开始）；该任务仍出现在“任务 → 已接受”列表中。
3. 在待处理考试中打开一条任务：看不到考生名单，只看到“接受后可查看考生名单”提示；点击“接受任务”后，待处理数量减少、待考试数量增加，详情中可打开考生名单。
4. 打开另一条待响应任务，点击“拒绝任务”：不选原因时“确认拒绝”不可点；选择原因并确认后，任务进入“任务 → 已拒绝”，详情中保留拒绝原因。
5. 打开 9 月 30 日 18:00 的已接受任务，点击“撤销接受”并选择原因：任务回到待处理考试，详情中保留“已接受后撤销”记录和撤销原因，且可重新接受。
6. 打开 9 月 30 日 13:30 已开始考试的已接受任务：不显示“撤销接受”，仍可查看任务信息和考生名单。
7. 分析页只展示统计数字、趋势和历史记录预览，不出现“优秀 / 良好 / 待改进”等未经确认的分数段；点击历史考评记录右侧的“更多”，可进入全部记录列表，用考试名称关键字和具体日期组合查询，“重置”可清空条件恢复全部。
8. 我的页面无“我的”标题，直接展示姓名、手机号、所属考点、累计考评次数、履职评分五项。
9. 全部页面不出现“行为预警”“开考”“开始考试”“评分操作”等内容。

## 范围说明

- 本原型只做本地状态演示，不模拟接口成功或失败；接入真实系统时，任务接受 / 拒绝 / 撤销需替换为接口调用并补充失败处理。
- 监考员、巡考员暂时只纳入统一框架，其专属任务内容和操作规则待需求确认后补充。

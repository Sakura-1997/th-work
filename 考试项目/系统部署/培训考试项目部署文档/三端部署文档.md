# 培训考试项目三端部署文档

## 1. 文档说明

本文档说明以下三个前端的构建及正式环境部署流程：

1. 赣服通端；
2. 培训机构端（`training-institution`）；
3. 办成一件事政务网端。

> **安全提示：** 本文档包含正式环境访问凭据，仅限授权人员在受控范围内保存和传阅。完成部署后，应关闭 SFTP、SSH 会话，不得将凭据、构建包或服务器信息上传至公共代码仓库或发送到非受控渠道。

## 2. 部署前准备

部署前确认以下事项：

- 本地已安装项目要求版本的 Node.js 和 npm；
- 已拉取待发布分支的最新代码，并确认版本号或提交记录；
- 已完成依赖安装、构建和必要的本地验证；
- 已确认本次发布对应的端、环境及构建命令；
- 正式环境操作前已获得发布授权，并预留回滚包；
- `dist.zip` 解压后必须得到名为 `dist` 的目录，否则后续 `mv dist ...` 命令无法执行。

## 3. 赣服通端

### 3.1 应用管理平台及环境

赣服通应用管理平台入口：

`http://10.5.18.47:8088/jpaas/appcenter/appmenu/application`

平台中的应用环境如下图所示：

![赣服通应用管理平台环境说明](./images/gft-deployment-environments.png)

| 平台应用 | 用途 | 数据环境 | 说明 |
| --- | --- | --- | --- |
| 测试应用 | 前端联调、测试及问题定位 | 与正式环境互通 | 带调试功能，便于前端测试和定位 Bug |
| 正式应用 | 正式对外发布 | 正式环境 | 提交审核后，通过邮件发布 |
| 旧应用 | 不再使用 | - | 已基本废弃，禁止继续发布 |

> 应用名称、应用标识、版本号、审核及发布规则以赣服通平台实际配置和赣服通官方文档为准。

### 3.2 构建命令

在前端项目根目录根据目标端执行对应命令：

| 构建目标 | 命令 | 产物用途 | 对接数据环境 |
| --- | --- | --- | --- |
| 网页 H5 应用 | `npm run build:dev` | 生成网页 H5 应用包，用于开发或测试联调 | 测试环境 |
| 赣服通正式小程序 | `npm run build:gft` | 生成赣服通正式环境小程序包 | 正式环境 |
| 赣服通测试小程序 | `npm run build:gfttest` | 生成带调试工具的赣服通测试包，用于前端测试及 Bug 定位 | 与正式环境互通 |

示例：

```bash
# 网页 H5 应用包，连接测试环境数据
npm run build:dev

# 赣服通正式环境小程序包
npm run build:gft

# 赣服通测试包，带调试工具且与正式环境数据互通
npm run build:gfttest
```

### 3.3 发布流程

1. 确认目标环境，执行对应构建命令。
2. 检查构建过程无报错，并核对产物生成时间和目标环境配置。
3. 将构建产物提交到赣服通对应应用：
   - 测试验证使用测试应用；
   - 正式发布使用正式应用；
   - 不得使用已废弃应用。
4. 测试包验证登录、核心业务流程、接口调用和页面显示。
5. 正式包验证无误后，在正式应用提交审核，并按赣服通流程通过邮件发布。
6. 记录发布版本、发布时间、操作人及验证结果。

> 赣服通第三方平台的登录、上传、审核、邮件发布及其他平台操作不在本文档展开，具体以赣服通官方文档为准。

## 4. 培训机构端（training-institution）

### 4.1 环境信息

| 项目 | 内容 |
| --- | --- |
| 环境 | 正式环境 |
| 堡垒机部署平台 | `https://10.11.4.241` |
| 堡垒机账号 | `许向东` |
| 堡垒机密码 | `Ai@tellhow2026123` |
| 目标服务器 | `10.11.60.14` |
| 更新文件 | `dist.zip` |
| 应用目录 | `/home/app/frontend/spt-dist` |
| Nginx 服务 | `nginx` |

### 4.2 部署步骤

1. 在 `training-institution` 前端项目中完成正式环境构建。
2. 确认构建产物目录为 `dist`，将该目录压缩为 `dist.zip`。
3. 浏览器访问堡垒机部署平台 `https://10.11.4.241`，使用上述账号登录。
4. 在堡垒机中选择目标服务器 `10.11.60.14`。
5. 通过堡垒机提供的 SFTP 功能，将 `dist.zip` 上传到目标服务器上的临时发布目录。
6. 通过堡垒机提供的 SSH 终端登录目标服务器，进入 `dist.zip` 所在目录。
7. 建议先保存当前 `/home/app/frontend/spt-dist` 作为回滚包，然后执行以下发布命令：

```bash
unzip dist.zip
rm -rf /home/app/frontend/spt-dist
mv dist /home/app/frontend/spt-dist
cd /home/app
docker-compose down nginx
docker-compose up -d nginx
```

8. 部署完成后执行验证：

```bash
cd /home/app
docker-compose ps nginx
docker-compose logs --tail=100 nginx
```

9. 访问培训机构端，检查首页、登录、静态资源、接口请求和核心业务流程。

## 6. 发布检查清单

### 6.1 发布前

- [ ] 已确认发布端和目标环境；
- [ ] 已确认代码分支、提交记录和版本号；
- [ ] 构建命令与目标环境一致；
- [ ] 构建无错误，产物内容及生成时间正确；
- [ ] 已保存当前线上版本或准备好上一版本构建包；
- [ ] `dist.zip` 解压后目录名为 `dist`；
- [ ] 已获得正式环境发布授权。

### 6.2 发布后

- [ ] Nginx 容器状态正常；
- [ ] Nginx 日志无明显错误；
- [ ] 页面可以正常访问，静态资源加载正常；
- [ ] 登录及核心业务流程验证通过；
- [ ] 浏览器控制台和接口请求无异常；
- [ ] 已记录发布版本、时间、操作人和验证结果。

## 7. 回滚说明

若培训机构端或办成一件事政务网端发布后出现严重问题，应立即停止继续操作，将对应应用目录恢复为发布前备份，再重启 Nginx 并重新验证。回滚时不得混用两个端的目录：

- 培训机构端：`/home/app/frontend/spt-dist`；
- 办成一件事政务网端：`/home/app/frontend/yjs-dist`。

回滚完成后，应记录故障现象、回滚版本、操作时间及处理结果。
